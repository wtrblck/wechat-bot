# 持续会话与换行回复（2026-11-05）

每个群、每个联系人保持一个独立的 DSH execution session。后续轮次只追加新增消息的正文、发言人、时间、消息ID和附件描述；发送状态发生变化时追加状态更新。不再每轮构造200条历史窗口，不运行独立参与判断、格式修复或发送前模型复审。

全局规则、人格、风格和参与策略在新上下文开始时冻结并持久保存。每批由同一会话自行决定是否参与；普通新消息在当前轮完成后进入队列，不取消已经生成的回答。停止、静默、重置、权限、费用和数据缺口保护仍由程序执行。

## 回复协议

直接输出普通文本，每个非空行对应一条微信消息，空行忽略。不再识别或兼容 `{"messages":[...]}`。

旁听、等待补充或没有合适内容时只输出 `[SILENT]`。程序拦截独立的标记行，不发送占位消息。通常一条回应就够，仍受最多30条/批和单条字节限制；过长内容按既有文件交付规则处理。

代码、诗歌、列表等需要保留内部换行时，模型使用 `send_text({text: ...})`，将完整内容作为一条消息排队。超出单条大小时创建并发送文件。`send_text`按本次输入和正文去重，只能发当前会话；排队不代表实际收件。

## 接近上限时才整理记忆

程序使用模型适配器声明的上下文容量，以及真实 usage 中未缓存输入、缓存输入和输出 token 判断占用。容量未知时使用65536 token备用容量，并用保守字节估计；不是供应商精确 tokenizer。

默认下一批加入后预计接近80%容量时提前交接，另留8192 token余量，避免等窗口完全用尽才无法总结。常规聊天中没有按条数、时间、空闲或积压量触发的后台摘要。

交接过程串行进行：

1. 在原 DSH 会话内发送内部整理请求，让模型读取已有完整对话及上一段记忆，整理人物偏好、重要事实、纠正、未完成任务、消息来源和实际操作状态。此轮无工具，输出不会发往微信。
2. 将记忆写入受保护文件和 `memory_segments` 索引，原始历史仍可按既有保留策略检索。
3. 原子切换到新的 DSH execution session，开头带固定规则、新记忆以及最多12条最近原始消息（原话交接最多24KiB），再处理尚未提交的新消息。

失败时保留旧会话和待处理输入，60秒后有界重试，最多4次；耗尽后暂停交接并记录原因。摘要已成功但文件发布失败时，重用持久输出，不重复付费调用模型。旧记忆和当前历史是资料，不继承旧任务的操作授权。

配置示例：

```yaml
sessions:
  isolation: conversation
  crossSessionMemory: false
  fallbackContextTokens: 65536
  rolloverRatio: 0.8
  reserveTokens: 8192
  recentMessages: 12
  maxSummaryChars: 6000
  summaryMaxAttempts: 4
```

模型别名变更时，下一轮先交接再切换模型。人格和全局风格保存后，在该会话下一段新上下文中生效；当前段的初始规则保持稳定。`/bot new`重置逻辑会话及任务权限，当前域已有记忆保留。`/bot compact`说明当前策略，不伪称执行了未发生的压缩。

## 重启、计费和升级

`conversation_contexts`持久保存执行ID、冻结提示词和容量状态。每轮通过 DSH 官方 resume 恢复同一个会话，再提交新的输入ID。恢复只读日志时按输入ID定位该轮，工具结果和最终回复不会误取后续轮次，也不会重新执行已有副作用。

逐请求预算仍按真实供应商 usage 结算。持续会话仍向供应商提交累计上下文，缓存命中也会计费；追加输入不代表只为新增消息收费。聊天和交接均计入每日预算。

升级时保留历史数据和账本，但取消旧机制尚未提交的JSON回复及旧决策/总结任务，不回退旧执行链路。已提交且状态不确定的发送仍保留原ID核对，不强制重发。
