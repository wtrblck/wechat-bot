# 连续上下文与分段记忆（2026-10-30）

回复和参与判断都读取当前会话最近最多200条原始消息，包含bot的已接受发送，按持久时间线排列。当前待回复消息用ID标记，在recent中只出现一次。出站请求获得原生message_id后，与微信回流合并，不会再将自己的回流当成新输入执行。跨群和私聊隔离保持不变。

## 上下文额度

`runtime.chatContextBytes: 196608`（192 KiB）只限制聊天资料，不扣固定提示词；固定提示词继续单独校验32 KiB上限，全部输入仍正常计费。这里明确使用UTF-8字节而非伪称精确token数，旧`contextTokens`/`memoryTokens`仅兼容旧配置，不再参与裁剪。附件描述单独有界；超大消息会明确标记truncated，只保留连续的最新消息后缀，不再跳过长消息后塞入无关的旧短消息。

每轮上下文保存`currentMessageIds`、`recent`、媒体描述、检索提醒与`contextStats`。不自动加入长期记忆。历史输入和本轮真实系统提示词保存在runs.input；`context_audit`额外记录消息数量、裁剪、系统/资料字节量和检索用量。每轮仍是独立dsh执行会话，连续性由上述完整时间线提供。

## 总结触发

每群/每私聊独立维护成功总结水位，条数同时包括双方发言：

- 满100条立即整理；积压150条时优先调度。
- 距上次完成10分钟且新增至少10条时整理。
- 静默3分钟且新增至少10条时提前整理。
- 低活跃会话满30分钟仍有未总结消息时整理；无新消息不调用。
- 单批最多100条/64 KiB，因长度分批时只能提交连续前缀，后续消息继续待处理。
- 全局每小时最多60次总结尝试，受原有每日5元、全局并发和模型超时约束。模型调用不是无条件立即完成，突发超200条时原始历史仍会保留待补总结。

总结使用独立执行ID、无工具、无角色人格的提示词，允许与同群回复并发（总并发上限内）。文件发布和索引/水位提交失败不会跳过消息；失败退避60秒。模型已输出有效摘要但文件发布失败时复用已保存输出，不重新付费调用；无效输出才创建新的重试执行。

## 摘要与文件

通常400～700中文字，硬上限1000；资料少时可短。只总结话题、结论、分歧、约定、背景和更正，不逐句抄录聊天。标签通常6～10个，最多10个，分为topics（话题）、entities（人物/对象）、states（状态/事项）、aliases（别称/关键表达）。各段可包含多个话题，不能把角色玩笑或bot猜测当成确认事实。

文件位于`data/memory/<scope>/<北京时间日期>/<segmentId>.json`，与模型可写沙箱分离。内容含摘要、标签、时间段、消息数和原始历史位置，不含原始消息列表。SQLite `memory_segments`提供索引，`summary_checkpoints`记录覆盖水位，`chat_history`保存可回查的原文。文件通过临时文件原子发布，读取时核对索引与文件内容，拒绝越界、链接及跨域读取。

## 模型按需检索

每轮提醒模型自行判断：当前200条能回答就直接答；涉及旧约定、往事、缺失背景或指代不明时，先查记忆；需要精确措辞或核实时再查原文。

1. `memory_search({keywords,before?})`：模型结合当前问题和对话提出关键词；只查标题和分类标签，不自动机械分词。按时间倒序，每批3个索引。关键词无命中或不足时，用空keywords从最近摘要向前回溯。nextBefore用于翻页。
2. `memory_read({ids})`：读取已列出索引的摘要，每批最多3段，每轮最多12段。通常6段内停止，找到足够信息立即停止。
3. `history_read({segmentId,before?})`：只能读取已读摘要对应范围内的原始历史，每批最多20条，每轮最多4批。返回的单批消息按正序排列，翻页从较新向较旧推进。

三种工具共享读取预算，默认8000估算token并有32 KiB字节硬上限，任一先到就停止；估算对中文按每字符2 token、ASCII按3字符/token、扩展Unicode按每字符4 token计算，含结构字段，属于保守压力估计，不声称提供厂商精确分词。费用仍按真实usage结算。累计工具执行时间15秒，模型生成和等待不计入该时间。索引最多搜索12次，另受已有每轮12次工具执行/步骤限制。超限、原文过期和没有结果明确区分，不能当成“没有发生过”。可通过memory.retrieval调整上限。

## 旧数据与保留

启动时做增量表迁移，原memory_units及费用/请求台账保持不动。一次性从已有授权Inbox和已接受Outbox重建chat_history，不重放模型、不发送旧消息；新的总结从可用原始历史生成，不将旧事实卡片伪装成新摘要。

原始历史默认保留7天，但尚未成功总结的chat_history不能因保留期到期而被删除。已成功覆盖的旧原文可按期清理，摘要文件及索引持续保留；查不到过期原文时工具会说明。dsh执行日志仍独立保留，未引入自动清理。

此改动不会自动启动bot，也不会为了迁移调用真实模型。建议先查看模拟回放报告，再显式启动进行真实群聊验收。
